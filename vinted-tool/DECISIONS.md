# Decisions

Choices made while building this without being able to ask. One line each on why.

- **Lives in `vinted-tool/` inside the existing `code-lab` repo, on branch `claude/zealous-tesla-aqt3yy`** — the session's repo already existed (a Next.js app), so instead of `git init` I kept the tool self-contained in a subfolder with its own `.gitignore`, venv and requirements.
- **Logged-in feature = favourites** — item 4 of the brief was left as "[FILL IN]"; favourites are the most useful thing to price-check, so `favourites` runs your saved items through the same identify + price pipeline. Saved searches/messages are not implemented.
- **Vinted data comes from server-rendered HTML in a real browser, not the `/api/v2` JSON endpoints** — tested 2026-11-19: the vinted.ie search page no longer calls `/api/v2/catalog/items` (it renders results server-side), and calling that endpoint directly returns 404 (plain HTTP) or 403 (from inside a browser session). Plain HTTP clients (httpx) get a Cloudflare JS challenge on `/catalog`; a normal Playwright Chromium session loads it fine. So: Playwright + parse the embedded Next.js flight data (`self.__next_f.push`), which has structured JSON (price, fee, total, brand, size, condition, photos).
- **Item pages are fetched for every result (on by default)** — the description, colour, category and postage are only on the item page; `--no-details` skips them for a quicker run.
- **Brand and size filters are applied client-side; max price and condition go into the Vinted URL too** — Vinted's brand/size filters need internal numeric IDs (size IDs differ per category), so the tool adds the brand to the search text and checks brand/size on each result. Condition maps to Vinted's `status_ids`, max price to `price_to`.
- **Up to 3 result pages are read to fill 50 filtered results** — client-side filters can drop items; capped at 3 pages to stay polite.
- **"Vinted price" in the report = item + Buyer Protection fee + cheapest shown postage** — the brief asks for the price including fee and postage where shown; the item-only price and fee are in their own CSV columns.
- **Default Claude model for photo ID is `claude-opus-5-5`** (override with `VINTED_TOOL_CLAUDE_MODEL`); only the main photo is sent, to keep cost down.
- **Retail price = cheapest *regular* (not-on-sale) new price of the matched product; sale prices noted** — first run used the cheapest new price, which was a women's colourway on sale at €120 against a €179.99 regular price, making most listings look dearer than new. Sales are colourway/size-specific, so the regular price is the fairer "buy-new" figure; any cheaper sale is written in the notes with its link. If every match is on sale, the cheapest sale price is used and flagged.
- **Sources are tried in order and the first source with a match as good as the identification wins** — follows the brief's priority (SerpAPI → brand site IE then UK → retailers); a weaker (different-variant) match is kept only as a fallback while later sources are tried.
- **Retailer search pages are read with a generic "product link + nearby price" extractor, then the chosen product page is checked via its schema.org data** — avoids brittle per-shop code; the product-page check confirms name, price, currency and stock.
- **Both the server-rendered and the client-rendered version of retailer pages are kept** — Foot Locker IE server-renders its results and then its client script replaced them with "no results" in the headless browser; other shops do the reverse.
- **Second-hand/resale sellers (eBay, Vinted, StockX, GOAT, Klekt, Laced, …) and kids' products are excluded from retail matches** — they aren't the buy-new adult retail price.
- **Collaborations (title contains "x Something") are capped at medium confidence** — collab retail prices differ a lot from the base model.
- **Variants that change the price (GTX/Gore-Tex, Expanse, S/LAB, Mid, …) must match for "high"** — a listing for the plain XT-6 priced against an XT-6 GTX would overstate the saving, so a variant mismatch drops to medium.
- **Discontinued status comes from the local product list (`"discontinued": true`) or a retailer's structured data** — there's no reliable live signal; such rows say "discontinued" and still use the last price found if any.
- **A Vinted item page that hits a bot-check is skipped (row keeps search-page data), then a 20 s pause; item pages stop after 3 blocks in a row; every other site is dropped for the run on its first block** — measured 2026-11-19: with 8–12 s spacing, about 3 in 10 vinted.ie item pages returned a 403 "Just a moment…" Cloudflare check while the next page loaded fine, so one 403 isn't "Vinted has blocked us". Retailer 403s (Salomon, Zalando, ASOS, JD) were consistent. The tool never waits on, interacts with or retries a challenge page.
- **Login autofill types the .env email/password into the form but never submits** — you still click "Log in" and handle any captcha; the credentials are passed straight to the page and never printed or stored by the tool (the saved session file holds only Vinted's cookies).
- **Report uses remote Vinted image URLs for thumbnails** — keeps reports small; they need internet to show photos.
- **The browser skips images, fonts, video and ad/tracker requests** — the tool only needs page HTML; vinted.ie item pages took ~60 s each with ads loading and ~5–8 s without. Lighter on every site too.
- **A listing's variant falls back only to the plain base model, never to a different variant** — an "XT-6 S/LAB" listing was first priced against an "XT-6 Expanse"; now it's priced against the plain XT-6 (flagged medium) or not at all.
- **On product pages that list many colourways/sizes, the most common price is used, not the minimum** — the minimum picked up another colourway's sale price; when the search tile's price appears on the product page, the tile price is kept.
- **Jackets: added outdoor price sources that load from here — 53 Degrees North (IE, EUR), Ellis Brigham (UK, GBP), Montbell UK (brand site, GBP); Foot Locker is now used for footwear only** — tested 2026-11-19: The North Face IE blocked (403), Arc'teryx IE/Patagonia/Mammut/Cotswold returned no product tiles; montbell.eu doesn't exist and montbell.jp prices are in JPY (not supported).
- **Retail brand can come from the product URL** — outdoor shops often title products "Beta GORE-TEX Jacket" with the brand only in the link (`/arcteryx-mens-beta-…`).
- **A retail product of a different item type never matches** (jacket listing vs "Downpour Pants"), and model matching uses the same longest-pattern rule as identification ("Beta" never matches "Beta AR").
- **`search` takes several queries, repeatable `--brand`, `--type` and `--must-mention`** — needed for "Gore-Tex jackets from good brands": one Vinted page per query, merged round-robin, filtered to the brands and to jackets, and kept only if the title/description mentions Gore-Tex/GTX (listings whose item page couldn't be read are judged on the title alone).
